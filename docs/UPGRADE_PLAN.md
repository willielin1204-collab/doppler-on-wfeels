## 1a. 雙偏振參數視覺化（ZDR / CC / KDP）

**科普說法**：一般雷達只會說「那裡雨很大」；雙偏振雷達同時發射水平與垂直兩種電波，等於多了一雙眼睛，能分辨**雨滴的形狀、種類，甚至看出龍捲風把碎片捲上天**。

**物理模型與公式（底層計算）**
- **ZDR 差分反射率**：`ZDR = 10·log10(Zh/Zv)` (dB)
  - 大雨滴受空氣阻力壓扁成橫向橢圓 → ZDR 大（+1~+5 dB）；小雨滴接近球形 → ≈0；冰雹翻滾 → ≈0 或負。
  - 實作：在降雨區依回波強度給正 ZDR（雨越大滴越大）；冰雹核 ≈0；TDS 碎片區 ≈0 或負。
- **CC / ρhv 相關係數**：水平與垂直回波的相關性，範圍 0~1
  - 純雨 0.97~1.0；融化層/混合相 0.85~0.95；**非氣象目標（碎片、昆蟲、地物）< 0.8**。
  - 實作關鍵：**TDS 區（鉤狀回波尖端＋速度偶極子處）CC 驟降到 < 0.7** → 自動標記「偵測到龍捲風碎片」。
- **KDP 比差分相位**：`KDP = dΦDP/dr` (°/km)，正比於液態水含量、不受衰減與校正影響
  - 強降雨 1~4 °/km；冰雹、雪 ≈0。實作：依液態降雨強度給值，冰雹核壓低。

**TDS 三條件（自動判讀）**：高 Z（≥45 dBZ）＋ 低 ZDR（≈0）＋ 低 CC（<0.8），且位於速度偶極子附近 → 顯示「🔴 TDS 龍捲風碎片標記確認」。

**資料模型**：擴充 `queryAtmosphereValue(x,y,mode)` 接受 `'zdr' | 'cc' | 'kdp'`，由現有風暴場（核心距離、鉤狀回波、TDS 半徑、是否觸發龍捲）推導，三者與既有 `reflectivity` 場物理連動。

**UI 與互動**
- `#radarMode` 下拉新增：差分反射率 ZDR、相關係數 CC、比差分相位 KDP。
- 每個參數一組專屬色標 + 一句科普說明（如 CC：「顏色越冷＝越可能是被捲起的碎片」）。
- 新增「TDS 自動判讀」小卡：即時顯示三條件是否同時成立。
- 每參數附「📐 原理」展開：放公式與物理一句話。

**整合**：PPI/RHI/Zenith 三視角皆支援新參數（沿用 `queryStormVolume` 的高度剖面）。

**❓ 待拍板**：① 五種模式是否要做「2×2 同畫面對比」鈕（同時看 Z/V/ZDR/CC）？還是維持單選下拉即可。

## 1b. 速度退疊（Nyquist Folding / Dealiasing）

**科普說法**：多普勒雷達測風速有個「最快只能量到 X」的上限，超過就會**像時鐘繞過 12 點一樣「折回去」**，讓朝你吹的狂風在畫面上看起來像在遠離——這是雷達判讀的經典陷阱。

**物理模型與公式**
- Nyquist（最大不模糊）速度：`Vnyq = λ·PRF / 4`，其中 `λ = c/f`（X 波段 λ≈3 cm）。
- 折疊：量到的視速度 `Va = ((V + Vnyq) mod 2·Vnyq) − Vnyq`。
- 退疊（unfold）：靠空間連續性把折回的值加回 `±2·Vnyq`。

**UI 與互動**
- 獨立小模組（或速度模式下的開關）：
  - **Nyquist 速度滑桿**（連動 PRF）：拉低 → 看到畫面開始出現假性反向色塊。
  - **「原始(折疊) ↔ 退疊後」切換**：左右對照，標出折疊邊界（速度色彩不連續的接縫）。
  - 龍捲風偶極子處風速最強，最容易示範折疊。
- 「📐 原理」：放 `Vnyq = λ·PRF/4` 與折疊公式，並點出與 ADC 取樣 Nyquist 是**同一個數學概念**（呼應 3. 方塊圖）。

**整合**：重用速度場 `queryAtmosphereValue(...,'velocity')`，外掛 fold/unfold 函式。

**❓ 待拍板**：② 做成「速度模式內的切換開關」還是「獨立教學區塊（含前後對照雙畫面）」？我建議後者，教學效果較好。

## 3. 雷達系統訊號鏈方塊圖（電機亮點）

**科普說法**：點一張會動的方塊圖，看一個電波從**產生→送出→打到雨→微弱回來→被放大解讀**的完整旅程，每一站都有對應的波形。

**訊號鏈（節點）**
`發射機(振盪源) → 波導 → 環行器/收發開關(T-R) → 天線(拋物面) →〔回波〕→ 低雜訊放大器 LNA → 混頻器(× STALO 本振) → 中頻放大 → I/Q 解調 → ADC 取樣 → 訊號處理(脈衝對/FFT → Z, V, W, ZDR, CC, KDP)`

**每節點顯示的波形/示意（Canvas 即時繪製）**
- 發射機：高功率脈衝列（pulse train，標 PRF/PRT）
- 波導：導波模態示意
- 環行器：發射時隔離接收、接收時導入 → 動畫箭頭
- 天線：窄波束輻射
- 回波：極微弱訊號（標動態範圍 ~ -110 dBm）
- LNA：放大後
- 混頻器：RF × LO → IF（外差降頻，畫頻譜搬移）
- I/Q：基頻 I、Q 兩路正交波形
- ADC：取樣點（呼應 Nyquist；取樣率不足 → 對應 1b 的折疊）
- 訊號處理：功率譜 → 三個矩(moment) Z/V/W，再到雙偏振量

**與電機專業的連結（差異化）**：外差接收、混頻、匹配濾波、I/Q 正交解調、FFT、ADC 取樣定理 —— 都是電機/訊號課程核心，氣象網站不會有這角度。

**UI**：橫向方塊圖，點/移過每個方塊 → 右側顯示該級的波形 Canvas + 科普一句 + 「📐 原理」公式（如混頻 `cos(ω_RF t)·cos(ω_LO t)` 產生和差頻）。

**❓ 待拍板**：③ 波形要「示意動畫」即可，還是要「可調參數」（例如拉 PRF 看脈衝列變化、拉取樣率看混疊）？後者更專業但工時較多。

## 2a. 雙都卜勒風場合成（Dual-Doppler）

**科普說法**：一台雷達只能測到「風往我這邊／離我多快」（徑向），測不到側向。**兩台 DOW 從不同角度同時看同一風暴**，把兩個徑向量交叉，就能還原出真正的二維風向量——這就是為什麼追風要派一整個車隊。

**物理模型與公式**
- 單雷達只得徑向分量：對雷達 i，`Vr_i = u·sin(az_i) + v·cos(az_i)`（忽略仰角與落速）。
- 兩台雷達 → 兩條方程式解二元一次，得水平風 `(u, v)`。
- 幾何品質：兩波束**交角接近 90° 最佳**，接近 0°/180°（基線方向）解會發散 → 顯示「雙都卜勒最佳觀測區（lobes）」。

**UI 與互動**
- 一張俯視圖：可拖曳擺放**兩台 DOW**，各畫出其徑向色場；中央合成出**風向量箭頭場（quiver）**。
- 疊加「最佳觀測雙葉區」；當兩車太近或共線 → 提示「交角不足，風場不可靠」。
- 連動車型資料庫：呼應「為何需要車隊」。

**整合**：重用 `getStormCenter()` / 速度場；新增線性解算與向量場繪製。

**❓ 待拍板**：④ 兩台固定 vs 可加到 3 台？⑤ 要不要顯示合成誤差/交角數值？

## 2b. 部署決策模擬（追風小遊戲）

**科普說法**：給你一張地圖、一顆移動中的超級胞、一張路網，由你決定 **DOW 停哪、天線朝哪、何時撤離**，事後依「資料品質」與「安全」評分——把追風的實戰判斷變成小遊戲。

**模型與評分**
- 超級胞沿風暴移動向量前進，含中氣旋/鉤狀回波/龍捲路徑帶。
- 玩家輸入：位置、天線方位、（可選）撤離時機與路線。
- **資料分**：與目標距離（太遠解析度差、太近危險）、波束是否被地物遮擋、（若雙車）交角。
- **安全分**：與龍捲路徑/RFD/大冰雹核的距離、依風暴移速估的撤離餘裕；進入路徑帶 = 重大扣分。
- 結算給評語（科普化的「追風教官講評」）。

**UI**：Canvas 地圖 + 道路 + 風暴動畫；放置/旋轉/設定撤離 → 「開始觀測」→ 結算卡。

**❓ 待拍板**：⑥ 範圍——**單一情境**（一次決策、快速結算，建議先這樣）還是**多回合關卡**？⑦ 是否需要計分排行/分享？
